- [ ] 阅读 `.trellis/spec/frontend/` 相关规范、Impeccable craft floor 与现有组件测试；记录现有未提交改动的边界，不覆盖用户工作。

## 2. 记录交互与状态

- [ ] 将 `MoodTorque` 调整为拖动预览、松手保持选择、显式确认；更新组件测试，覆盖重复松手、未拖动、禁用、低动效和确认前无提交。
- [ ] 在今天页将草稿、待确认、提交中、失败重试、成功撤销串成单一状态路径；更新幂等 ID 生成时机和页面测试，覆盖网络失败、跨日、离开页及重试。
- [ ] 保留当前 API 契约；不修改后端记录字段与共鸣计算。

## 3. 外观选择与场景

- [ ] 实现本机白名单外观设置与回退默认值：小鹿/山雀、小叶树/山茶花灌木；从“我的”切换并在今天页即时生效，标明不跨设备同步。
- [ ] 用用户提供的 PNG 构建分层场景，基础植物和动物独立切换；五段心情痕迹可共存，删除/撤销重新计算，低动效保留静态可读状态。
- [ ] 检查图片包体、透明边缘、路径和微信构建；缺失素材显式作为待交付依赖。

## 4. 三页信息设计

- [ ] 今天页：场景、记录控件、共鸣、时间线建立明确先后顺序；空、加载、失败、撤销、选中记录状态完整。
- [ ] 回顾页：七日植物视图、趋势、日历、洞察保持可扫描且在无数据时有内容；不把花/灌木错误称树。
- [ ] 我的页：外观、触觉/低动效、私密说明、导出/删除分组；危险操作层级和文案清楚。
- [ ] 更新导航/页面的明亮色系，确保 H5 与微信小程序都有足够对比度、触控面积和窄屏布局。

## 5. 验证与交付

- [ ] 运行相关 Vitest、`pnpm lint`、`pnpm typecheck`、`pnpm build:h5`、`pnpm --filter @mood-record/miniapp build:mp-weixin`。
- [ ] 启动 H5 开发服务，检查手机与桌面视口的真实页面截图；素材到位后批量修正一次并复核一次。若无法使用浏览器自动化，说明限制并要求用户提供微信开发者工具实机反馈。
- [ ] 运行 Impeccable 检测器一次；检查素材来源和授权记录，完成设计文档与 Trellis 质量检查。
- [ ] 交付时明确列出已完成、待用户放置的素材及视频后续项，不将缺图页面称为最终视觉完成。

## 风险与回退点

- 当前 `apps/miniapp/src/pages/today/index.vue`、`me/index.vue` 与多项测试已有用户未提交改动；逐文件合并，禁止覆盖或重置。
- 图片生成由用户完成，资产质量和到位时间影响最终视觉验收；代码工作可先完成状态机与布局，图片入库后再做一次最终验收。
- 视频暂不接入；如果未来加入，静态场景是可靠回退，低动效不播放。
- 旧 MVP PRD 同步时只改 R1/R2 及直接相关验收，不扩大到后端和部署规则。
