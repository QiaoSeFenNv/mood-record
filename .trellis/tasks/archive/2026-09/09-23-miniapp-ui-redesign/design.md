# 小程序界面重设计：设计与技术方案

## 现状与边界

- `apps/miniapp` 是 uni-app / Vue 3 页面；H5 只是可视化预览，微信小程序仍是交付目标。
- 现有深色渐变、发光树和通用大圆角卡片不是新视觉的约束。保留心情树机制、功能链路、三页主导航、隐私及估算口径。
- 记录交互改为拖动预览、松手后显式确认；提交成功仍提供 5 秒撤销。须同步更新旧 MVP PRD 中 R2 的冲突条款和相关测试。
- 新世界采用 Operate 模式：树要有存在感，但记录动作、状态和数据解释优先于装饰。

## 视觉方向研究

核心机制：一次心情记录给当天同一棵树留下一层可辨的痕迹；同一天的情绪并存，时间线与回顾有可追溯的对应关系。实际使用场景是用户在手机上用几秒完成私密记录。类别惯性是柔和植物日记卡片，反向惯性是黑底霓虹情绪仪表盘；两者都不能直接作为新方向。

按用户识别度与产品表达力排序的七种材料世界（其中只有一个直接借用树的字面意象）：

1. **植物观察标本页**：一棵树作为被持续观察的对象，时间、痕迹和记录像标本旁的索引；易理解，但有滑向常见植物日记的风险。
2. **乐谱与音轨**：一天的不同情绪像音色和声部叠加，强度控件天然可映射为滑杆；树要成为可读的叠层图，而非音乐装饰。
3. **套色版画**：每次记录给树叠一层不同墨色，重叠并非覆盖；首屏由开放的树形印迹、紧凑的数值预览和确认控件组成，可延伸到七日森林。这是本轮种子分配的方向。
4. **城市路线图**：一天沿时间前进，记录是节点，分支是不同情绪；定位清楚，但容易把个人感受做成通勤工具。
5. **织物色线样本**：每次记录是一束线，交错形成树冠和周视图；柔和而有触感，制作和数据可读性成本较高。
6. **色彩实验记录册**：五段情绪不是好坏等级，而是可并置的颜料样本；树通过色块叠合显影，存在过度抽象的风险。
7. **陶瓷釉色试片**：每次记录像一层釉面，沉积可见；材质鲜明，但连续值与精确时间的交互不够直接。

Impeccable `concept-seed`：Operate / direction，种子 `44370704`，指派第 3 项。候选挑战者按“用户识别度、产品清晰度”两轴评估：

| 挑战者 | 判定 | 理由与可借鉴纪律 |
| --- | --- | --- |
| 张力雕塑 | declined | 结构状态虽可视化，但“松弛/失败”会暗示情绪好坏；保留输入与反馈一一对应的纪律。 |
| 深海潜游 | declined | 暗色与危险叙事不适合私密、非评判记录；保留层级与进程同向变化的纪律。 |
| 复印店 zine | declined | 强制字列和跳色纸张让轻量记录变重；保留一屏一个清楚叙述重点的纪律。 |
| 机场导引 | competitive | 清晰的下一步指示有利于确认保存，但公共设施语气缺少私密感。 |
| 黑白数据场 | declined | 闪烁、高密数字与低动效和温和语气相冲突；保留精确数据标记的纪律。 |
| 胶片剪辑台 | declined | 时间顺序清晰，但黑橙高张力与树的共存机制不合；保留可回看且可定位的时间刻度。 |

## 用户反馈与方向重置

- 第一轮方案被用户整体否定。选择页上的“深海潜游”不代表视觉批准，不能据此实现。
- 用户给出的参考是带蓝紫天空、柔和光感、草地与陪伴角色的移动产品宣传图。借鉴的是色彩、轻盈感与陪伴关系；实际页面不照搬宣传拼图或原有角色。
- 人物改为原创动物伙伴，植物允许用户选择，首版分别提供 2 种后再迭代。形象只参与视觉反馈，不进入心情记录或共鸣计算。
- 首次进入使用默认组合，在“我的”选择；偏好保存在本机，不新增后端设置接口。登录身份变化时避免将一个测试用户的形象选择错误展示为另一人的账号设置。
- 两种植物不是两种树，而是一棵树与一种花或灌木。默认树维持“心情树”的产品识别；替代植物仍要完整呈现五段痕迹，视觉映射共享情绪语义而不是另设业务枚举。
- 选定后记录页面方向契约，再细化组件、状态、微信兼容与验收计划。

## 最终拟定的视觉世界

以用户参考图为视觉锚点，设计为“日光草坡上的心情植物”：蓝紫与浅粉的明亮天空承担情绪氛围，草地和独立植物插画形成场景；小动物是安静的陪伴者，不做情绪评分。此方向由用户参考直接指定，覆盖种子 `44370704` 的全部第一轮方案。配色不是暗色霓虹，也不是奶油色日记卡片：场景用蓝紫、青绿与少量暖金，操作界面使用高对比的浅色面和深绿色文字。

首屏的植物场景不装入浮动卡片，约占手机首屏的上半部分；日期与记录数置于清楚的顶端区域，植物和动物有可读剪影；下半部是连续滑杆、当前数值和情绪名称、明确的“记下这一刻”确认按钮。无记录时植物仍在，已有记录的五种痕迹能共存；拖动只预览，确认后痕迹落定。回顾与我的继承同一色彩、插画与排版规则，但弱化场景，优先提供可扫描的数据和设置，不把每块内容装成卡片。

初版候选素材建议为小鹿、山雀、小叶树和山茶花灌木，默认小鹿加小叶树。物种只是艺术选型，不进入业务模型；最终素材由用户按 `asset-prompts.md` 生成。图像保留场景与角色分层，天气、露珠、柔光、金叶和花朵用轻量图形痕迹实现，而不是为每个动物 x 植物 x 情绪组合生成整张图片。原图仅作色彩与气氛参考，不复刻构图或角色。

## 组件与数据边界

- `MoodTorque` 管理滑杆交互和可确认草稿，拖动与松手均不得调用 API。松手后保持当前预览；只有显式按钮点击向页面发出提交事件。继续拖动会更新草稿。
- “今天”页面负责草稿、提交中、失败待重试、成功撤销窗口的状态机。一次确认只生成一个 `clientMutationId`，失败重试复用该标识；提交中禁用重复确认。切换日期或离开页面时清除未提交的临时预览。
- 现有 API `createMood`、`today`、`resonance`、`deleteMood` 和响应契约保持不变。视觉选择不入后端记录，也不影响聚合口径。
- 现有 `MoodTree` 重构成可分层的植物场景：读取记录和预览值，按五段心情叠加确定性痕迹；选择植物只替换基础插画，选择动物只替换陪伴插画。删除或撤销后由剩余记录重新计算。减少动画时停用非必要运动而不隐藏痕迹。
- 使用本机 uni storage 保存两个白名单选项，未知旧值回退到默认值，不新增后端设置接口。它是设备外观偏好，不宣称绑定账号或跨设备同步；测试身份切换仍沿用本机外观，界面明确标为本机设置。
- 主导航和页面路由保留。回顾页把原本密集的卡片改成可扫描的七日视图、趋势和日历；植物可选时避免把灌木误称为“树”。我的页分清外观、体验设置、数据与隐私；危险操作仍沿用确认对话框。

## 素材与性能

- 静态 PNG 放在 `apps/miniapp/src/static/scene/`，文件名、尺寸、透明要求和生成提示词见 `asset-prompts.md`。素材尚未到位时不能宣布视觉验收通过。
- 主场景底图与动植物分层加载；情绪痕迹由小型图形元素承载，数量受可见记录和稳定槽位限制，避免每条记录产生一层全屏图片。保留 `reducedMotion` 的静态关键帧。
- 视频仅列为以后可替换的可选背景。微信小程序包体、播放限制、自动播放、低动效和真机耗电未验证前不接入首版；静态背景始终存在。
- H5 用于桌面与手机宽度的视觉检查，最终小程序兼容以 `build:mp-weixin` 和微信开发者工具/真机复核为准。

## 兼容与回退

- 原 MVP PRD 的 R2“松手即保存”改为“松手后显式确认”；相关验收与测试同步更新，不保留两套规则。
- 原 MVP PRD 的 R1“固定梦幻发光树 + 6-8 帧序列”改为本任务批准的原创分层场景；保留五段情绪非惩罚性痕迹、记录共存及低动效完整可读的行为要求。
- 如新资产加载失败，记录控件和数据仍可用，页面提供轻量静态后备状态并暴露可诊断错误；不能用空白区域冒充已完成的场景。
- 变更主要限于 `apps/miniapp` 页面、组件、设置和测试及相关 PRD。无需数据库迁移或 API 部署。回退时旧版 UI 可恢复，后端数据不受外观偏好影响。
