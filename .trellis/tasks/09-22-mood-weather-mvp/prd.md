# 心情晴雨表 MVP

## Goal

打造一款以“心情树”为核心视觉的微信小程序，让用户无需写长日记，也能在 5～10 秒内记录此刻情绪、观察一天内的情绪变化，并通过匿名的聚合反馈感受到“此刻有人和我一样”。

产品目标是连接真实后端、可在微信开发者工具运行且具备上线基础的微信小程序，而非仅供演示的交互原型。当前阶段先以仅限本地开发环境的测试身份连通小程序、API 和数据库，验证真实存取与聚合链路；由于尚无小程序账号和 AppID，真实微信登录、正式环境调用与发布留待后续阶段。MVP 首先验证“快速记录 + 即时共鸣”能否形成持续使用习惯；产品不提供心理诊断或治疗结论。

## User Value

- 低负担：不写文字也能完成一次有意义的记录。
- 可观察：保留每次记录的真实时间，呈现一天和一周内的变化。
- 有共鸣：记录完成后看到不可识别个人的今日聚合反馈；基础数据来自去重用户，放大后的展示值明确标注为估算。
- 非评判：所有情绪都被接纳，不用“好情绪奖励、坏情绪惩罚”诱导用户。
- 重隐私：个人记录默认私密，用户能够导出和删除自己的数据。

## In Scope

- “今天 / 回顾 / 我的”三个一级页面。
- 梦幻发光风的心情树、连续心情扭矩、24 小时时间轴和保存后的 5 秒撤销。
- 当天匿名共鸣、七天心情森林、日历、趋势和事实型洞察。
- 本地测试身份、真实 API 与持久化数据库链路。
- UTF-8 CSV 导出、单条删除、全部清除和账号注销。
- 为微信登录、订阅消息和正式发布保留清晰接入边界，但当前阶段不真实启用。

## Requirements

### R1. 首页与心情树

- 用户进入小程序后直接看到当天的心情树和“记录此刻”入口，不先展示任务墙或强制填写表单。
- 当天首次及后续每次记录都对树产生可见变化。
- 不同心情留下的叶片、雨滴、光影等痕迹可以在同一棵树上共存；删除或撤销某条记录后，根据剩余记录重新生成当天的树，不残留已删除的痕迹。
- 树的主背景始终保持中性，同日最后一条记录不得覆盖或主导之前的痕迹。
- 树与五种心情痕迹使用梦幻发光风的高质量分层插画，拖动和记录完成时呈现逐帧动效；设备性能不足或用户开启低动效时展示清晰的静态关键帧，不阻断记录。
- 素材由本项目原创生成并进行风格统一，不使用来源或授权不明确的第三方插画；关键变化以 6～8 帧序列表达，其余连续效果使用代码动画，低动效模式只展示静态关键帧。
- 情绪以不同但同样具有审美价值的天气、光影、叶片或花朵效果表达；负面情绪不得使用枯萎、死亡、扣分等惩罚性表达。
- 五段痕迹固定为：`很低落 → 蓝紫雨滴 + 根部柔光`、`有点低落 → 蓝雾 + 露珠 + 缓慢光流`、`平静 → 青绿光晕 + 呼吸效果`、`比较愉快 → 暖金新叶 + 萤光粒子`、`很愉快 → 发光花朵 + 金色星点`。
- 首页同时展示当天的 24 小时时间轴，记录节点按真实时间定位。

### R2. 快速记录

- 首页提供一个横向连续“心情扭矩”控件，左负向、中平静、右正向；单次滑动同时表达情绪方向与程度，首版核心记录不再要求额外选择情绪、强度、标签或填写文字。
- 拖动过程中持续显示当前扭矩值和“很低落 / 有点低落 / 平静 / 比较愉快 / 很愉快”之一，不用隐晦天气词代替情绪名称。
- 拖动过程中只做心情树预览，不写入数据；用户松手并完成提交后才创建一条记录，避免滑动过程产生多条记录。
- 松手后立即保存，一次完整手势最多创建一条记录；网络重试不得创建重复记录。保存成功反馈出现后，在页面底部提供 5 秒“撤销”。
- 5 秒内点击“撤销”无需二次确认，须删除刚创建的记录，并同步更新树、时间轴、回顾与共鸣；重复撤销保持幂等。若该用户当天还有同一区间记录，去重共鸣人数不得错误减少。
- 用户完成一次滑动即可提交，标准路径目标耗时不超过 10 秒。
- 连续值在后台按等宽规则映射为：`-100～-61 很低落`、`-60～-21 有点低落`、`-20～20 平静`、`21～60 比较愉快`、`61～100 很愉快`。用户无需再做第二次选择；天气效果只负责视觉表现。
- “负向更沉、正向更顺滑”不得改变最终选值精度或造成无法提交；设备不支持触觉反馈、用户关闭震动或启用低动效时，控件仍保持完整可用。
- 保存失败时不得伪装成功，应保留本次选择并提供重试；重试沿用同一幂等标识。
- 同一用户同一天可记录多次，系统不得用“每日仅一次”或固定时段唯一约束覆盖已有记录。
- 用户可点击时间轴节点查看该次记录的时间和扭矩结果。
- 已提交的记录不提供编辑入口；撤销窗口过后只能删除。删除后重新滑动产生一条以新提交时间为准的记录，不覆盖旧记录的时间和内容。

### R3. 即时共鸣

- 每次完成记录后，展示当天相同扭矩区间的匿名估算人数、清晰的“今天”口径和一句温和、非诊断、非说教的反馈。
- 基础计数必须来源于真实记录，并按去重用户口径计算，不能因同一用户重复提交而增加。
- 展示值采用 `基础去重人数 × 动态系数`，系数随基础人数增长从最高 10 逐步降至 1；界面以“约 X 人”和“基于匿名活跃趋势估算”明确披露，而不是将调整值声称为精确实时人数。
- 当前用户不进入基础人数；公式及边界固定为：`0 → 不展示人数`、`1～10 → ×10`、`11～999 → ×√(1000/N)`、`1000 及以上 → ×1`，最终四舍五入为整数。该公式保证基础人数增长时估算值不反向下降。
- 默认统计用户当地自然日内的同类情绪去重用户，并在界面明确标注“今天”；服务端以请求携带的用户时区计算边界，避免按服务器时区错误跨日。时间范围使用可扩展枚举而非写死单一路径。
- 当前用户从基础人数中排除；基础人数为 0 时不编造“有人”的表述。首版固定当天窗口，不自动扩大到其他日期。
- 共鸣只统计情绪枚举等必要字段，不展示任何用户身份、原文或可反推出个人的信息。
- 完成反馈后允许用户直接离开，不强制分享或进入连续任务。

### R4. 个人回顾

- “今天”展示心情树和 24 小时时间轴。
- “回顾”至少展示七天心情森林、日历、7 天趋势及简单洞察。
- 洞察只描述可验证的事实和关联，不使用心理诊断、人格判断或情绪好坏评分。
- 示例包括记录次数、常见负向或正向时段、一天内心情扭矩的变化。

### R5. 隐私控制

- 个人情绪记录默认私密，不公开给其他用户，也不用于好友比较、排行榜或广告画像。
- “我的”页面提供匿名化说明、震动反馈开关、低动效开关、个人数据导出、单条删除、全部清除和账号注销入口；首版不展示无实际发送能力的提醒开关。
- 数据导出生成 UTF-8 CSV，字段至少包括记录时间、时区、扭矩值和五段心情名称；不得导出其他用户数据、鉴权凭据或内部敏感标识。
- 单条删除、全部清除和账号注销必须在危险操作前明确确认，成功后在线数据立即移除且不可由用户恢复；备份副本最迟 30 天内清理，期间处于隔离状态，不参与展示或统计。
- 身份信息与情绪记录应以内部匿名标识关联，服务端和日志遵循最小化采集原则。

### R6. 导航与基础体验

- MVP 主导航保持为“今天 / 回顾 / 我的”三个一级页面。
- 文案统一使用接纳、克制的表达，避免“治疗、治愈、诊断、你的情绪很差”等医疗或评判性措辞。
- 无数据、网络失败、重复提交和跨日场景需要有明确且可恢复的反馈。

### R7. 本地开发与后续正式接入

- 本地开发环境提供可区分测试用户的身份入口，用于验证个人记录隔离、一天多次记录、回顾与共鸣聚合；该入口不得在正式部署配置下启用。
- 前后端本地连通真实的数据读写；共鸣展示即使采用动态系数，也必须可追溯到基础去重人数和明确算法，不使用任意写死数字；测试数据与未来真实用户数据隔离。
- 微信登录及正式环境服务域名配置保留清晰的接入边界，待取得 AppID 和完成平台配置后联调；当前验收不宣称已完成微信登录或公开发布。

## Acceptance Criteria

- [ ] 新用户进入首页后，无需填写文字，可在正常操作路径中于 10 秒内完成首次记录。
- [ ] 用户在同一天连续记录多次后，每条记录均被保存，并准确显示在 24 小时时间轴的对应位置。
- [ ] 拖动时清晰显示当前数值和五段名称；松手最多创建一条记录，重复网络请求由幂等标识收敛为同一结果。
- [ ] 保存成功后出现 5 秒撤销入口；撤销后该记录不再出现在树、时间轴、回顾或共鸣中，重复撤销不会重复删除或产生错误数据。
- [ ] 撤销窗口过后无法修改既有记录的扭矩值或时间；删除并重新记录会生成新的记录时间，树、时间轴与共鸣按当前有效记录重算。
- [ ] 每次成功记录都会让当天的树发生与该次情绪对应的可见变化，任何情绪均不会触发惩罚性枯萎或扣分。
- [ ] 一天内连续记录低落、平静、愉快后，树上可看见各次记录的共存痕迹；删除中间记录只移除其对应效果，其他痕迹仍保留。
- [ ] 首页包含精细的心情树插画及与滑动、记录相响应的逐帧变化；低动效模式和性能降级下仍能识别五种痕迹并完成记录。
- [ ] 记录完成页展示匿名聚合反馈和实际统计窗口；接口区分基础去重人数与最终展示值，动态系数可测试、可审计且不会低于 1 或高于 10。
- [ ] 共鸣估算公式在 `N = 0、1、10、11、999、1000` 等边界值上符合已确认规则，并且展示值随基础人数增加保持非递减。
- [ ] 默认共鸣仅聚合用户当地当天的数据，跨日后自动进入新窗口；接口能够安全拒绝未知时间范围，并为后续新增区间保留兼容性。
- [ ] 用户可查看七天森林、日历及基于真实记录生成的事实型洞察。
- [ ] 用户可导出数据、删除单条记录、清除全部记录并发起账号注销，操作结果清晰可验证。
- [ ] 导出的 CSV 可由常见表格软件正确显示中文，并且仅包含当前用户的记录时间、时区、扭矩值和五段心情名称等约定字段。
- [ ] 删除、清空或注销成功后，相关在线数据立即无法查询且即时退出树、时间轴、回顾、洞察与共鸣计算；隔离备份不得被在线业务读取，并在不超过 30 天内清理。
- [ ] 其他用户无法查看个人记录内容，共鸣接口不返回可识别个人的信息。
- [ ] 核心流程覆盖无记录、网络失败、重复点击提交和日期切换场景。
- [ ] 所有用户可见文案不包含医疗诊断或承诺治愈的表达。
- [ ] 当前阶段的代码可按说明运行和验证；真实微信登录、正式环境调用与发布依赖后续取得 AppID 及完成平台配置，不把开发身份或测试数据伪装成真实用户或公开共鸣人数。
- [ ] 当前代码可按说明完成质量检查、微信小程序构建和 API 启动，服务重启后有效记录仍然存在。
- [ ] 用两个不同的本地测试身份创建记录时，只能分别查看、导出、删除本人的私密记录；共鸣由本地数据库中的测试记录计算，并明确标识为测试环境。
- [ ] 正式环境配置无法启用开发身份入口；缺少真实微信登录配置时应拒绝受保护 API 请求，而不是自动放行。
- [ ] 认证层为后续微信登录保留可替换边界；切换认证提供方不要求修改记录、回顾、共鸣和隐私接口，关键数据不依赖写死的演示数据。

## Out of Scope for MVP

- 匿名树洞、公开日记、评论、私信及好友关系。
- AI 心理陪伴、心理诊断、危机干预机器人。
- 年度报告、排行榜、复杂徽章或养成任务。
- 首版快速记录中的标签、自定义标签和文字日记。
- 已导出数据的再次导入或跨账号迁移。
- 心理咨询交易、会员付费、企业 EAP 与任何个人情绪数据对企业的提供。
- 微信订阅消息、打卡提醒开关及定时推送；只为后续接入保留清晰边界。
- ClickHouse、MongoDB 等尚无明确数据规模依据的额外基础设施。
- Redis、MySQL/PostgreSQL 和多 API 实例部署；达到经测量的并发或容量瓶颈后再评估迁移。

## Risks and Deferred Release Dependencies

- 情绪记录属于高度敏感数据，需要最小化采集、传输加密、服务端访问控制、审计和明确删除机制。
- 即时共鸣存在冷启动风险。用户提出动态放大展示值；若将调整值直接称为真实人数而不说明，会与隐私优先和可信产品定位冲突，并可能损害用户信任。
- 精细分层插画和较丰富的逐帧动画显著增加素材制作、包体及性能成本；设计阶段需确定帧数、资源加载与低端设备静态降级方案。
- SQLite 简化了 MVP 运维，但限定为本地磁盘上的单实例部署；若未来需要横向扩容、跨主机高可用或持续高并发写入，必须迁移到服务型数据库。
- 当前无小程序账号和 AppID；注册、取得 AppID、完成小程序自身备案、隐私协议核验与接入微信登录均为正式发布依赖，不阻塞本地 MVP。订阅消息已延后，届时还须核验模板和用户授权规则。
- 现有 API 域名的 ICP 备案主体、HTTPS 证书及微信后台 request 域名配置须在发布前实测核验；已有 ICP 备案不等于小程序备案或公安联网备案。
- 纯 API 服务是否适用公安联网备案，由服务器所在地主管部门或接入商在发布前确认；当前不自行认定豁免。
- 用户在 Cloudflare 部署的另一个项目前端与本产品无关，不作为本产品的部署或备案依据。
